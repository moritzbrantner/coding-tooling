For coding agents

Inspect first.
Then edit.

Use coding-tooling as a deterministic structural preflight before changing a public GitHub repository. Pin the repository revision when the task names a branch, tag, pull request head, or commit, then continue with the repository's own instructions and authoritative validation.

Required first step

Repository preflight

  1. Identify the repository as owner/repository. If the task is tied to a branch, tag, pull-request head, or commit, also identify that exact ref.
  2. Open https://moritzbrantner.github.io/coding-tooling/?repo=<owner>%2F<repository>. Append &ref=<percent-encoded-ref> when an exact revision is known. Percent-encode substituted repository and revision values; Git refs can contain characters such as #, +, and & that otherwise change the URL's meaning.
  3. Use the result as remote structural evidence only. It can inspect public GitHub metadata, repository structure, bounded manifests, declared capabilities, and published evidence; it cannot execute the repository.
  4. Read the target repository's AGENTS.md and other governing files before editing. Repository-local guidance and declared commands take precedence over generic assumptions.
  5. Keep revision-sensitive work pinned. Do not substitute default-branch analysis for a task that names another ref.
  6. Before claiming the work is ready, use the repository's authoritative local or CI validation on the exact resulting head.

Copyable instruction

Minimal agent rule

When asked to work on a public GitHub repository, discover the machine analysis transport first:
https://moritzbrantner.github.io/coding-tooling/analysis-endpoint.json

If it reports status "available", use its http-json hrefTemplate with the percent-encoded owner/repository and, when known, the exact ref.

If the HTTP transport is not configured, browser-capable agents may use the Pages preflight:
https://moritzbrantner.github.io/coding-tooling/?repo=<owner>%2F<repository>

Do not send caller cookies or caller GitHub authorization through the analysis service. Treat all remote results as structural evidence only, then read AGENTS.md and verify the exact resulting head with authoritative local or CI checks.

Agent-oriented views

Use the narrowest useful surface

HTTP analysis discovery

Start with this static JSON contract. When status is available, its hrefTemplate is a conventional application/json endpoint suitable for plain HTTP clients. 

https://moritzbrantner.github.io/coding-tooling/analysis-endpoint.json

Browser fallback

Browser-capable agents can still use the existing client-rendered projection. Plain HTTP readers must not mistake this Pages route for a server-side JSON endpoint. 

https://moritzbrantner.github.io/coding-tooling/analysis.json/?repo=<owner>%2F<repository>&view=agent&envelope=1

Focused analysis

Narrow existing evidence with supported focus, component, severity, finding, or change-aware parameters rather than inventing a second analysis path. 

https://moritzbrantner.github.io/coding-tooling/analysis.json/?repo=<owner>%2F<repository>&view=agent&focus=testing&min-severity=medium&envelope=1

Change-aware planning

When base and head refs are known, use affected-component analysis to derive a conservative validation plan. 

https://moritzbrantner.github.io/coding-tooling/affected.json/?repo=<owner>%2F<repository>&base=<percent-encoded-base-ref>&head=<percent-encoded-head-ref>&tier=fast

Full machine contract

Read agent-tool.json for the published operations, parameter types, authority levels, completeness semantics, and limitations.

Authority boundary

GitHub Pages remains a zero-install observation surface. It does not clone the repository, run tests or builds, inspect private repositories, mutate repository state, or establish semantic correctness. Browser JSON views are browser-executed static pages. The separately deployed analysis Worker is only a transport adapter around the same remote analyzer; it does not gain local execution authority. Missing, stale, bounded, or unavailable evidence must not be treated as passing evidence.

Do not

Common agent mistakes

  • Do not treat remote preflight as a replacement for exact-head CI or local checks.
  • Do not infer semantic correctness from structural findings or repository shape.
  • Do not ignore an explicit task ref and analyze only the default branch.
  • Do not interpret unavailable or incomplete evidence as success.
  • Do not use the browser surface to perform repository mutations.
Deterministic preflight before repository work. Local and CI execution remain authoritative.
